# 预览控件、字体与图标统一设计

日期：2026-08-05

## 目标

修复透明工具栏在手机预览中显示为黑色的问题，并统一编辑器字体、图标和画布控制。预览仍必须忠实读取每个皮肤的颜色、透明度、图片和字体；编辑器不得用固定颜色覆盖皮肤声明。

## 渲染分层

手机预览按“手机内容背景 → 半透明 iOS 键盘底材 → 皮肤画布 → 皮肤图标”合成。候选栏声明的透明色不绘制；半透明和不透明皮肤仍按原 alpha 绘制。键盘底材覆盖候选栏、主键盘和底部附件区，因此透明工具栏最终呈半透明灰，而不是直接透到手机内容。

避免在透明 Canvas 的祖先上使用会触发 WebKit 黑色合成块的模糊方式；键盘底材改用稳定的半透明灰。键盘顶部增加轻微亮边。深色手机内容背景使用柔和深灰和现有渐变，不使用近纯黑底色。

## 字体与图标

编辑器 UI 字体优先使用 `PingFang SC`，再回退到 Apple 系统字体和通用无衬线字体。皮肤画布、候选文字和皮肤声明的字体不被强制替换。

SF Symbols 是 Apple 平台的原生符号体系，但当前界面运行在 WebView 中，无法从 DOM 直接调用。本轮在 Tauri Rust 层增加 macOS AppKit 桥，使用 `NSImage(systemSymbolName:accessibilityDescription:)` 在运行时取得系统符号；前端把返回的透明 PNG 作为 CSS mask，继续以 `currentColor` 着色。不得把 SF Symbols 字体或导出的 Apple glyph 资源打包进仓库。非 Tauri 浏览器预览使用小型自绘 SVG fallback，不声称它是 Apple 官方资源。

左侧导航、文件夹、文本文件、图片文件和手机模拟界面的返回、撤销、重做、分享、更多、完成、地球与麦克风均使用同一符号体系。符号只负责视觉，不改变按钮文本和可访问名称。应用 Dock 图标继续使用自有键盘图案，不使用 SF Symbol。

## 画布控制

画布顶栏保留设备选择，并新增：

- 方向分段控件：竖屏 / 横屏。
- 外观分段控件：浅色 / 深色。
- 缩放控件：减号、百分比、加号，范围 50%–150%，步进 10%，默认 100%。

缩放通过 CSS 自定义属性改变 `device-shell` 的显示尺寸，不改变 Canvas 像素尺寸、坐标换算或导出内容。滚动画布允许查看放大后的完整设备。

右侧检查器删除布局和外观分段控件。布局仍通过左侧“9键”和“26 键”条目切换；外观与方向通过画布顶栏切换。隐藏的原生 `select` 继续作为单一状态源，减少事件逻辑重写。

## 测试

- 透明皮肤色不产生背景填充，半透明和不透明颜色继续绘制。
- 手机键盘底材是半透明灰，工具栏 DOM/Canvas 保持透明，且不存在会导致黑块的祖先模糊合成。
- 深色手机背景不是近纯黑，键盘顶部存在亮边。
- 顶栏包含方向、外观和缩放控件；右侧不再包含布局分段控件。
- 缩放值被限制在 50–150，并按 10 递增；设备逻辑坐标不变。
- 左侧文字为“9键”；文件夹、文件及主要界面按钮具有统一 symbol 图标和可访问文本。
- UI 字体优先为 `PingFang SC`，皮肤字体解析逻辑保持原样。
